# PipeOS control server -- the part that runs anywhere.
#
# Everything here installs on a Mac, a Linux box or the Pi with no compiler and
# no hardware present. That is the point of the split: the console, the run
# store, the API and the tests are all exercised on a laptop, and a laptop must
# not have to build a GPIO driver to run them.
#
#   requirements-pi.txt      the robot's hardware: GPIO, the IMU. Pi only.
#   requirements-detect.txt  serving the defect model. Laptop only.
#
# On the Pi, install into a venv created with --system-site-packages so
# picamera2 and the apt-managed libraries stay visible. See docs/HARDWARE.md.
#
# NOT installable with pip on Raspberry Pi OS -- use apt for these:
#   sudo apt install python3-picamera2 python3-gpiozero python3-lgpio
#
# OpenCV drives USB cameras AND the optical-flow odometry. Without it the server
# still runs; distance falls back to duty integration and reports that it has.
#   sudo apt install python3-opencv

fastapi==0.115.6
uvicorn[standard]==0.34.0
websockets==14.1
pydantic==2.10.4

# NO onnxruntime, AND THAT IS THE POINT. The defect model does not run on the
# robot: RF-DETR on a Pi 5 is seconds per frame with the cores pinned and the
# board hot, and between the runtime and the graph it costs most of a gigabyte
# of SD card for the privilege. The robot posts frames to a laptop instead and
# needs nothing but the standard library to do it -- see perception/remote.py.
#
# To serve the model from a laptop:  pip install -r requirements-detect.txt

# Tests. Safety and estimator tests need no hardware and run anywhere.
pytest==8.3.4
